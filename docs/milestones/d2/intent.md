# D2 Intent — Shell, Design System, and First-Launch Onboarding

## Outcome
A new user can install and open OSCA, understand its research-only boundaries, choose or create a local profile, verify storage and sidecar health, load sample data, and reach a coherent desktop home surface.

## Scope
Desktop navigation shell, design tokens and reusable accessible components, profile selection, first-launch flow, storage-location explanation, sample-data path, diagnostics summary, and initial Home information architecture.

## Non-goals
Provider credential workflows, production charts, analysis creation, recommendations, simulated trading, or live execution.

## Dependencies
D1 desktop application API, sidecar lifecycle, and protocol compatibility.

## Risks
WebView inconsistency, inaccessible component foundations, confusing product boundaries, profile corruption, and onboarding that requires paid services.

## Exit intent
Clean-profile onboarding succeeds on supported macOS and Linux targets; keyboard and screen-reader paths are evidenced; offline sample use works; failure states explain recovery; later milestones can reuse the design system without bypassing application services.

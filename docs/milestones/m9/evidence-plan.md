# M9 Evidence Plan

## Evidence objectives

- Prove ML registry contracts preserve deterministic identity and lineage.
- Prove feature and label definitions fail closed for point-in-time and leakage risks.
- Prove evaluation reports require holdout evidence before promotion.
- Prove promotion does not automatically approve paper challenger deployment.
- Prove manual testing documentation is updated for M9 usage surfaces.

## Planned evidence

| Slice | Evidence |
|---|---|
| M9.1 | Contracts, service gates, tests, ADR, requirements, OpenSpec, and manual testing update. |
| M9.2 | Training workflow planning, immutable experiment/model registry persistence, and artifact import/export metadata. |
| M9.3 | F2/F3 integration, champion/challenger paper deployment decisions, drift/outcome monitoring, and retraining records. |
| M9 closeout | Accepted spec, archived OpenSpec, exit review, final Quality evidence, and manual testing refresh. |

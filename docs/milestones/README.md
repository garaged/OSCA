# Milestone Documentation

OSCA milestone documentation is organized by delivery generation and milestone identifier.

## Desktop product generation

The accepted desktop-product authority consists of:

- `docs/product/desktop-product-intent.md`
- `docs/roadmaps/desktop-product-roadmap.md`
- `docs/product/cross-cutting-requirements.md`
- `docs/product/desktop-capability-map.md`
- `docs/product/desktop-traceability.md`
- `docs/milestones/desktop-spec-template.md`

D1 is specified at implementation level under `docs/milestones/d1/`. D2-D19 each contain a solution-light `intent.md`. When a milestone starts, its intent must be expanded using the desktop specification template and reconciled with current evidence before implementation.

## Governance

Intent documents fix the user outcome, product boundaries, dependencies, primary risks, and exit intent. They do not pre-authorize speculative APIs, schemas, providers, libraries, or migrations. Those details become authoritative only through the milestone's executable specification and accepted decisions.

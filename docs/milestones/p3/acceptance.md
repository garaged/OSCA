# P3 Acceptance Criteria

| ID | Requirement | Criterion | Evidence |
|---|---|---|---|
| P3-AC-001 | REQ-0177 | Provider catalog contracts represent candidate identity, cost model, access mode, capability fit, disposition, source URIs, and constraints. | Tests and inspection |
| P3-AC-002 | REQ-0178 | Default profiles preserve P2 dispositions for all catalog candidates and exclusions. | Tests |
| P3-AC-003 | REQ-0179 | Preferred no-cost profiles are limited to SEC EDGAR and FRED until later evidence changes the catalog. | Tests |
| P3-AC-004 | REQ-0180 | Conditional candidates classify as needing evidence before adapter-contract planning. | Tests |
| P3-AC-005 | REQ-0181 | Research-only and excluded providers cannot become default implementation-ready. | Tests |
| P3-AC-006 | REQ-0182 | P3 explicitly does not implement adapters, invoke APIs, handle credentials, route providers, or promote providers. | Inspection |
| P3-AC-007 | REQ-0183 | Requirements, traceability, ADR, OpenSpec, manual testing, and hosted Quality evidence are retained. | Hosted Quality and inspection |

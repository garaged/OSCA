# M4 Acceptance Criteria

- **Status:** Active
- **Source:** [M4 scope](scope.md)

| ID | Criterion |
|---|---|
| M4-AC-001 | Projects have stable identity, owner-visible objective, horizon, status, and immutable creation metadata. |
| M4-AC-002 | Project timelines record decisions, hypotheses, data revisions, analysis runs, outputs, and promotions as typed events. |
| M4-AC-003 | Hypotheses capture assumptions, expected outcomes, invalidation conditions, confidence, and lifecycle state. |
| M4-AC-004 | Ad hoc exploration can be promoted into a project without losing declared dependencies. |
| M4-AC-005 | Analysis graphs declare typed nodes, inputs, outputs, parameters, dependencies, quality policy, and interval requirements. |
| M4-AC-006 | Graph validation detects missing inputs, duplicate node identifiers, cycles, and unsupported provisional data use. |
| M4-AC-007 | Analytical outputs distinguish observations, signals, findings, theses, recommendations, alerts, and reports. |
| M4-AC-008 | Outputs retain provenance to project, analysis graph, dataset revisions, parameters, and producer version. |
| M4-AC-009 | Visualization specifications reference governed outputs rather than raw internal storage. |
| M4-AC-010 | Visualization exports include reproduction metadata and disclosed aggregation or downsampling. |
| M4-AC-011 | Documentation, OpenSpec, traceability, and evidence are updated before M4 exit. |
| M4-AC-012 | M4 does not weaken M3 temporal correctness or provider licensing deferrals. |
